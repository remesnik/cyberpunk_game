# Cyberspace Spheres and Security Sleeves

A Sphere is persistent logical subnet membership. Every runtime node has a `sphere_id`; legacy content is placed in an explicit unassigned Sphere until authored classification is added. A Sphere records its member node IDs and the ID of the Security Sleeve those nodes originally shared.

A Security Sleeve describes current protection and segmentation. Its `current_members` and state may change when security is breached, bypassed, disabled, or split. These operations never mutate node `sphere_id` or `SphereDefinition.node_ids`.

For example, splitting `SLEEVE_A` into A1 containing nodes 1–2 and A2 containing node 3 leaves node 4 outside active protection. All four nodes still belong to Sphere A. The tactical Sphere minimap therefore continues to show every known node in Sphere A while drawing current known sleeve protection separately. An unprotected node remains visible without the sleeve marker.

Only `NetworkGraph.move_node_to_sphere()` performs an explicit logical reconfiguration. It is intended for authored story or network-reconfiguration effects, not ordinary security compromise.

The tactical minimap uses `SphereMinimapNode`, a dedicated small-hex renderer. It shares the main graph's configured unknown and security-level styles but deliberately ignores ordinary capability content. Its marker vocabulary is limited to current player position, SAN, objective, detected ICE, Sphere exit, and critical alert. Feeds, datastores, databases, software, and other inspection detail remain in the primary graph and inspector.

Player location is an additive high-contrast ring and inner process marker, leaving the node's security fill and border intact. The local SAN uses the same deck-link glyph language as the main graph and is tethered above its host hex. These markers have separate anchors, so a player standing in the SAN host shows both states clearly. Player movement and SAN knowledge changes refresh the minimap independently; relocating the SAN (including through Doorstop) moves only its marker and never changes Sphere membership.

Recent hacker movement is owned by `HackerTrailSystem`, not by the minimap. The minimap requests only trail segments visible to the local actor and draws them as faint dashed emphasis over already-known connections. Segment opacity comes from authoritative tick decay, so newer movement is clearer and old movement disappears naturally. Own-trail rendering can be disabled through `CyberspaceVisualizationConfig.minimap_show_own_trail`; hostile trails remain hidden until the trail system records detection by the local player.

Current Security Sleeves are an optional subordinate overlay, never a source of minimap membership or layout. Known nodes sharing a current Sleeve receive a faint partial boundary mark, while known links within that Sleeve receive a low-opacity security tint beneath the ordinary connection. Splitting, disabling, or otherwise changing a Sleeve refreshes these decorations only; every known node remains in its persistent Sphere position. `minimap_show_security_sleeves` and the associated color, opacity, and width properties control this layer, and `SphereMinimap.set_security_sleeves_visible()` provides the runtime settings hook.

Security and placement mutations maintain an explicit authority boundary. `NetworkGraph` emits a Sleeve-change notification for simulation and story consumers, but the minimap continues rendering the last observed Sleeve record until a scan, sensor, story event, or other legitimate source commits the new state to `PlayerKnowledge`. Intact protection is drawn continuously; observed breached, split, or bypassed protection is subordinate and dashed. A temporarily unprotected node remains on the map because its persistent `sphere_id` did not change.

Safe SAN placement follows the same rule. Host-bound ICE can be silently displaced in authoritative simulation before a SAN is created or relocated, but that placement operation never reports the destination to `PlayerKnowledge`. The previous observation naturally becomes stale unless another information source reacquires the ICE. Roaming ICE is not displaced. Doorstop relocates the single SAN instance and updates the local SAN knowledge marker atomically; its defenses and integrity move with it, while Sphere membership and hacker trails remain untouched.

Known links leaving the current Sphere terminate in fanned boundary arrows rather than drawing foreign nodes. Each link gets an independent marker, so one node can expose several exits. `PlayerKnowledge` stores Sphere identity separately: a discovered destination is labeled with its known Sphere name, while an undiscovered identity is rendered as `UNKNOWN NETWORK REGION`. Crossing the link changes `CurrentSphereTracker`, causing the minimap to rebuild from the new Sphere's known topology; it never expands both Spheres into one map.

The compact minimap header is also knowledge-only. Sphere ID/name, total topology size, and security state are independent `PlayerKnowledge` facts. It always reports the number of currently known nodes, but shows a denominator only when topology size has been explicitly learned. Until then, `KNOWN NODES: 8` is valid while `8 / 14` would be an authoritative-data leak.

Minimap nodes are lightweight focus controls, not traversal controls. Hover or keyboard focus shows only the sanitized known name (or `UNKNOWN NODE`), while activation emits `network_node_focus_requested` for the primary cyberspace display. A locally rendered node is highlighted there; a known distant node is reported as outside the current local view. No minimap handler calls `NetworkGraph.traverse()` or spends an action. The optional center-player button issues the same harmless focus request, and collapse/expand remains independent.

Sphere minimap LOD is semantic. Small maps show compact labels; medium maps shorten labels; dense maps retain every known node, security hex, known connection, player, SAN, objective, Sphere exit, critical alert, and immediate ICE threat while omitting labels and passive low-priority ICE markers. Mouse-wheel zoom progressively restores medium and close inspection detail, and middle-button drag pans the enlarged map. Center-player resets the pan around the current node. Crossing to another Sphere resets zoom/pan and rebuilds the new player map. Thresholds and zoom limits live in `CyberspaceVisualizationConfig`.

Static knowledge (node existence, discovered links, and Sphere membership) does not age. Dynamic observations store `observed_tick`, `stale_after_ticks`, and optional expiry independently in `PlayerKnowledge`. Current ICE and system observations use solid markers; stale ICE becomes a faded outlined last-known marker with its observation age, and stale process/status markers become outlines. Temporary-route overlays similarly fade before expiry. Unknown or expired dynamic information is absent. Advancing knowledge time never queries authoritative positions, so the minimap cannot provide omniscient tracking.

Authoritative Sphere membership is never equivalent to the player map. `SphereMinimapCanvas` filters members through `PlayerKnowledge`: undiscovered nodes and links are absent, discovered nodes with unknown level are grey, and known levels use their configured style. Its compact layout is calculated only from currently known nodes, so hidden members do not reserve positions or disclose their count through suspicious gaps. Level/content updates do not move nodes; a genuine topology discovery may compactly reflow the map.

`PlayerKnowledge.reveal_sphere_topology()` supports routing tables, story intelligence, or similar effects that disclose a whole subnet. It reveals node existence and internal connections while leaving security levels, hosted contents, and capabilities unknown unless the information source explicitly reveals those facts separately.

## Debug fixture

`res://tests/SphereMinimapDebug.tscn` is a dedicated interactive mutation lab. It contains ten authoritative nodes in `SPHERE_ALPHA`, seven in `SPHERE_BETA`, partial discovery and level knowledge, distinct player/SAN locations, a live trail, current and stale ICE intelligence, an objective, split Sleeve groups, an unprotected historical member, and a known boundary route. Its controls exercise the real graph, knowledge, SAN, trail, Sleeve, and Sphere-tracking APIs for discovery, level intelligence, Sleeve break/restore, SAN relocation, player movement, ICE visibility/staleness, and Sphere transition.

Run it directly from the Godot editor with **Play Current Scene (F6)**. The status block always shows Alpha's authoritative member count and the unprotected node's persistent Sphere, making accidental membership mutation immediately visible.
